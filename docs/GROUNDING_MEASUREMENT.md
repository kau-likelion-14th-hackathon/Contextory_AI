# 근거 판정(Grounding) 실측 기록

> 측정일 2026-08-19 · 대상: 세 파트 저장소의 병합된 PR 30건
> 재현: `python -m scripts.measure_grounding --limit 12 --repeat 3 --json out.json`

## 왜 쟀는가

검색 최고 유사도가 `SIM_THRESHOLD` 미만이면 **LLM을 아예 호출하지 않고** "근거 부족" 화면으로 빠진다.
이 임계값을 감으로 정하면 두 방향 모두 나쁘다.

- 너무 높다 → 멀쩡한 PR도 초안 없이 "사람이 직접 확인하세요"만 나온다
- 너무 낮다 → 무관한 컨텍스트를 근거라고 붙여 잘못된 초안을 만든다

그래서 실제 PR의 점수 분포를 먼저 쟀다.

## 1차 측정 — 임계값 자체는 타당했다

PR 30건(AI 9 / 백엔드 9 / 프론트 12)의 최고 유사도 분포:

| 임계값 | 초안 생성 | 근거 부족 | 빠지는 비율 |
|---:|---:|---:|---:|
| 0.45 | 28 | 2 | 6.7% |
| **0.50** | **26** | **4** | **13.3%** ← 현재 |
| 0.55 | 18 | 12 | 40.0% |
| 0.60 | 9 | 21 | 70.0% |

**임계값을 0.55로 올리면 40%가 초안 없이 빠진다.** 0.5는 유지가 맞다.

## 2차 측정 — 진짜 문제는 임계값이 아니었다

같은 PR을 3회씩 반복 측정하니 **판정이 실행마다 뒤집혔다**.

```
✗ #12  Contextory_AI       0.4954 / 0.5177 / 0.4982
✗ #38  OffCourse_FrontEnd  0.4977 / 0.5798 / 0.4978
```

24건 중 2건(8.3%). 같은 PR을 두 번 분석하면 한 번은 초안이 나오고 한 번은 안 나온다는 뜻이다.
**임계값을 어디로 옮겨도 고쳐지지 않는 종류의 문제다.**

### 원인 — 무작위성이 아니라 쿼리 길이

검색 쿼리는 LLM이 PR 제목·본문을 영문으로 번역해 만든다. 그 번역이 흔들렸다.

```
0.4462  "project domain CRUD API implementation"
0.5458  "... Project entity, ProjectMember entity, ProjectStatus Enum, ProjectPermissionRole Enum ..."
```

기존 프롬프트가 **"concise"** 를 요구해서, 유사도를 만들어내는 기술 식별자를 버리고 있었다.
짧게 요약된 쿼리는 임베딩 검색에서 불리하다 — 즉 결정성만 고정했다면 이 PR은 *항상* 근거 부족으로
빠지는 오탐이 됐을 것이다.

## 조치

| 조치 | 내용 |
|---|---|
| 재현성 | `TRANSLATION_TEMPERATURE=0.0`, `TRANSLATION_SEED=42` (`core/config.py`) |
| 쿼리 품질 | 번역 프롬프트를 "간결하게 요약" → **"식별자를 원문 그대로 남기고 요약하지 말 것"** 으로 변경 |

두 값 모두 `core/config.py` 설정이며 `.env` 로 덮어쓸 수 있다. 코드에 상수를 박지 않았다.

## 남은 것

- 여전히 근거 부족으로 빠지는 1건은 프론트 PR이다. 임계값 0.5 기준 4.2%이며,
  저장소 초기 PR처럼 **참조할 과거 컨텍스트가 실제로 없는 경우**가 섞여 있다 — 이건 정상 동작이다.
- `SIM_THRESHOLD` 는 **0.5 유지**를 권한다. 올리면 40%가 빠지고, 내려도 얻는 게 없다
  (0.45로 내려도 추가로 통과하는 건 1건뿐).
- 저장소 코드가 바뀌면 분포도 바뀐다. 재인덱싱 후 이 측정을 다시 돌려 확인할 것.
